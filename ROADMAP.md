# Roadmap mvi

План развития: поддержка форматов, новые функции и инфраструктура.
Статус документа: актуален для v1.0.0.

## Обозначения в таблицах

| Значение | Смысл |
|---|---|
| `+` | готово и работает |
| `±` | частично (есть ограничения/дефекты) |
| `-` | нет, план на фазу указана в примечании |

## Таблица поддержки форматов

| Формат | Расширения | Просмотр | Редактирование | Примечание |
|---|---|---|---|---|
| Markdown | `.md` `.markdown` `.mdown` `.mkd` `.mkdn` `.mdwn` `.mdtxt` `.mdtext` | `+` | `+` | glamour-рендер, темы, таблицы; правка: встроенный vim-движок или внешний nvim/vim |
| Текст | `.txt` `.log` `.text` `.csv` | `+` | `+` | сырой режим: отображается дословно, без markdown-искажений |
| Код | `.go` `.py` `.js` `.rs` `.sh` `.yaml` `.json` и т.д. | `+` | `+` | подсветка синтаксиса (chroma) с наследованием темы; без лексера — дословный текст |
| Makefile, конфиги | `Makefile` `.ini` `.conf` `.toml` `.env` | `+` | `+` | дословный просмотр; подсветка — если найден лексер |
| reStructuredText | `.rst` | `+` (сырой) → v2.0 | `+` | сейчас как текст (теги/разметка видны дословно); нативный рендер — v2.0 |
| AsciiDoc | `.adoc` | `+` (сырой) → v2.0 | `+` | как rst |
| Org-mode | `.org` | `+` (сырой) | `+` | нативный рендер вне плана |
| HTML | `.html` `.htm` | `+` (сырой) → v2.0 | `+` | теги видны дословно; режим исходника с подсветкой — v2.0 |
| LaTeX | `.tex` | `+` (сырой) | `+` | разметка видна дословно |
| Изображения | `.png` `.jpg` `.gif` | `-` | - | отклоняются как бинарные; только при наличии sixel/kitty-графики (research, вне плана) |
| PDF | `.pdf` | `-` | - | отклоняется как бинарный; вне плана |
| Двоичные | любые | `+` (защита) | - | детект по содержимому (magic bytes / управляющие символы) + отказ с сообщением |
| Файлы без расширения | — | `+` | `+` | тип определяется по содержимому (первые 8 КБ) |

Автозапуск без аргумента (`mvi` в каталоге): `README*` → любой markdown → `.txt`/`.log`/`.text` → браузер.

## Фазы

### v1.1 — «Универсальная читалка» (высокий приоритет)

Превращает приложение из markdown-читалки в просмотрщик любых текстовых файлов.

Выполнено:
- **Классификация файлов**: тип по содержимому (первые 8 КБ: нулевые байты,
  доля управляющих символов) и расширению → markdown / text / binary.
  Бинарность важнее расширения: `x.md` с `\x00` не откроется.
- **Защита от бинарных файлов**: отказ с сообщением
  «формат не поддерживается» вместо пустого мусора.
- **Сырой режим просмотра** для не-markdown: без markdown-разметки,
  `\t` → пробелы (шаг 4), длинные строки переносятся по словам,
  содержимое отображается дословно; JSON разворачивается с отступами.
- **Больше markdown-расширений**: `.mdx`, `.rmd`, `.qmd`.
- **Markdown по содержимому**: файлы без расширения (README, CHANGELOG)
  с заголовком `# …` открываются как markdown.
- **Автозапуск без аргумента**: README → любой markdown → `.txt`/`.log`/`.text`
  → браузер.
- **Метка типа в статусбаре**: `md`, либо расширение файла (`go`/`py`/`txt`).
- **Создание файлов в браузере**: `n` — новый файл (создаётся и сразу
  открывается), `N` — новый каталог; ввод имени с проверкой на дубликаты
  и запретом разделителей пути.
- **Удаление файлов в браузере**: `d` → подтверждение (`d` — да, `esc` —
  отмена), без рекурсии — непустой каталог не удаляется.
- **Ссылки в документе**: `o` в просмотре — список всех ссылок
  (inline `[текст](url)`, голые URL, autolink), `enter` открывает:
  http(s)/mailto — наружу через `xdg-open`, относительные пути — внутри
  mvi (файл открывается, каталог — в браузере).
- **История переходов по ссылкам**: `ctrl+o` — назад, `tab`/`ctrl+i` —
  вперёд (как в vim), с восстановлением позиции прокрутки файла;
  новый переход очищает ветку «вперёд», недоступный файл — история
  не теряется.
- **Поиск по документу**: `/` — запрос в статусбаре (enter искать,
  esc отмена), `n`/`N` — следующее/предыдущее совпадение с wrap,
  переход к ближайшему совпадению с центрированием экрана,
  счётчик «совпадение i/n», регистронезависимо; сброс при открытии
  файла и перерендере.
- **Бесшовное открытие файлов**: `file://`-ссылки открываются в этом
  же терминале (внутри mvi), наружу через `xdg-open` уходят только
  настоящие внешние ссылки (http/https/mailto).

Осталось:
- **Поиск в просмотре**: `/` — поиск, `n`/`N` — следующее/предыдущее,
  подсветка совпадений (ANSI-подчёркивание).
- **Перенос строк** в просмотре: включить существующую опцию `soft_wrap`
  (в конфиге есть, в UI не подключена).
- **Порог больших файлов**: предупреждение при открытии > 5 МБ
  (для сырого режима лимит поднять до 50 МБ).

### v1.2 — «Красивый код» (высокий приоритет)

Выполнено:
- **Подсветка синтаксиса** через chroma (`alecthomas/chroma`):
  - отдельные файлы кода (`.go`, `.py`, …) — лексер по имени файла,
    без лексера — дословный текст;
  - цветовая схема наследуется от темы mvi (monokai/github/dracula/
    tokyonight-night; для ascii/notty подсветка отключается);
  - перенос строк и JSON-отступы выполняются до подсветки — ANSI не ломается.

Осталось:
- **Блоки кода внутри markdown** — унифицировать схему с glamour
  (glamour рендерит блоки сам, своя подсветка поверх не ставится).
- **Таблицы markdown**: проверить и выровнять рендер длинных таблиц
  (glamour умеет, но нужен регрессионный тест).
- **Номера строк в просмотре** для кода (опция, по умолчанию выключена).

Критерии готовности:
- `.go`-файл подсвечен, переключение темы меняет и подсветку — ✅ есть тесты;
- блоки кода в `.md` подсвечены в обеих темах — осталось;
- есть тест рендера таблиц (golden-файл) — осталось.

### v1.3 — «Навигация и буфер» (средний приоритет)

- **Fuzzy-поиск файлов**: `ctrl+p` — мгновенный поиск по дереву каталога
  (вместо пошагового `j/k` в браузере).
- **Недавние файлы**: история в `~/.config/mviewer/recent.json`,
  клавиша `R` в браузере (или отдельный пункт меню).
- **Системный буфер обмена**: OSC52 — `yy` в просмотре и `y` в vim-редакторе
  копируют в терминальный буфер (работает в tmux при включении).
- **Быстрый переход к строке**: в просмотре `:{число}` или `g{число}G`.

Критерии готовности:
- `ctrl+p` находит файл по подстроке за < 100 мс на дереве в 10 000 файлов;
- копирование работает минимум в xterm-совместимых терминалах и tmux;
- переход на строку доводит заголовок к верху экрана.

### v1.4 — «Масштаб» (средний приоритет)

- **Ленивый рендер**: для длинных документов рендерить только окно
  просмотра (сейчас glamour обрабатывает весь файл целиком).
- **Открытие огромных файлов**: 100 МБ plaintext — < 1 с, стабильная память.
- **Режим только для чтения** для файлов > лимита (защита от случайной правки).
- **Профилирование**: флаг `--debug` (pprof), бенчмарки рендера
  в CI для отлова регрессий.

Критерии готовности:
- бенчмарк: открытие 100 МБ без блокировки UI > 50 мс;
- память при прокрутке 50 МБ документа не растёт линейно.

### v2.0 — «Экосистема» (низкий приоритет, по demand)

- **Другие разметки**: rst (выбор парсера — исследование, варианты:
  `go-restructuredtext`, внешние конвертеры), asciidoc.
- **Пользовательские стили glamour**: `~/.config/mviewer/styles/*.json`
  (вместо восьми встроенных тем).
- **Экспорт**: markdown → HTML (и, как research, PNG через терминальный рендер).
- **Пакетирование**: AUR, Homebrew, deb/rpm; man-страница; автодополнение
  для bash/zsh/fish.
- **CI/CD**: GitHub Actions (vet + test + lint), goreleaser с релизами.

## Вне плана (won't do)

- WYSIWYG-редактирование и LSP-интеграция (внешние редакторы уже закрывают).
- Просмотр изображений без sixel/kitty (research-задача, не факт что возьмём).
- Работа с PDF.
- Рендер HTML как в браузере (полноценный layout в терминале не проектируется).

## Приоритеты

Порядок фаз отражает влияние на пользователя: сначала «чтобы ничего не
ломалось на чужих файлах» (v1.1), затем эстетика (v1.2), затем удобство
навигации (v1.3), затем производительность (v1.4). Голосуйте за пункты —
порядок внутри фаз можно менять.
